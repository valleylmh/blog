# 一句话生成一本绘本：聚焦一个免费提供商后，插图终于像同一本书了

![周末陪童童骑行红蓝跑道](/images/articles/20260910/cover.png)

StoryBloom 最早接入生图能力的时候，我的策略是"能用的都用上"。

Agnes、Pollinations、Cloudflare、通义万相、HuggingFace，五六家提供商按页轮流分配。第 1 页用 Agnes，第 2 页用 Pollinations，第 3 页轮到 Cloudflare，依此类推。每家都有免费额度或免费模型，加在一起刚好够一本 8 页绘本。

这个方案解决了生图成本的问题，却制造了一个更严重的问题：一本绘本翻到第三页，主角就变了个人。

## 万国牌的代价

不同提供商用的是不同模型，即使拿到完全相同的 prompt，画出来的风格、色调、人物比例、背景氛围也会明显不同。一本讲"童童周末骑行"的绘本，前两页是暖色水彩风的小男孩，第三页突然变成冷色调 3D 渲染的另一个孩子，第四页又跳到平面矢量风格。

对大人来说，这只是"画风不统一"；对孩子来说，主角换了。

![从多提供商到统一风格的一致性对比](/images/articles/20260910/consistency.png)

我试过用更详细的 prompt 约束角色外观，也试过加 Character Bible 让每页都描述同一套特征。效果有改善，但治标不治本。因为不同模型对 prompt 的理解方式本身就不一样，同一句"穿黄色外套的男孩"在五个模型眼里是五个孩子。

## 收拢到一个免费提供商

后来我做了一个看起来"倒退"的决定：把所有页面的插图都交给同一个提供商。

最终选了 Agnes。它有免费的 API 额度，生成速度够快，而且同一个模型在不同 prompt 之间保持了比较一致的画风和人物处理方式。8 页绘本由同一个模型画出来，风格、色调和角色特征自然就统一了。

当然，单一提供商不意味着没有容错。代码里仍然保留了 fallback 机制：如果 Agnes 在某一页超时或报错，会自动尝试其他配置好的提供商。但正常情况下，一本绘本从头到尾都走同一条路径。

这个改动不算有技术含量，甚至算不上一个功能。但它解决了之前最让人难受的体验问题。

## 现在的效果

打开 StoryBloom，输入一句话，比如"周末陪童童户外活动骑行红蓝跑道"，系统会先生成完整的 8 页中英双语故事，然后逐页生成插图。

因为所有插图都由同一个模型生成，画面里的孩子从第 1 页到第 8 页看起来像同一个人，场景的色调和氛围也前后连贯。不需要登录注册，不需要下载应用，打开网页就能用。
![](/images/articles/20260910/p1.jpg)
生成完成后，可以在线阅读、朗读、导出长图、生成带旁白的竖屏视频，也可以通过分享链接发给家人。
